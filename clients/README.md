# Client conformance

`clients/js/test/conformance.test.mjs`, `clients/python/tests/test_conformance.py` and `clients/rust/tests/conformance.rs` run the same scenarios against a live gateway:

1. create a payment with an idempotency key
2. replay the same key and body: same payment id
3. same key with a different body: 409
4. create a lightning attempt on the mock provider and pay it through the mock provider hook
5. receive the `payment.paid` webhook on a local receiver and verify its signature
6. a tampered body and a wrong secret are rejected
7. get shows `paid`, a partial refund completes, listing by reference returns the payment

`clients/test-vectors/webhook.json` holds signature vectors generated by the server code (`cargo run --example webhook_vectors`). Every client checks its signing against them.

## Run

```
export TEST_DATABASE_URL=mysql://root:test@127.0.0.1:33907/
scripts/start-test-gateway.sh > /tmp/gw.env
set -a; . /tmp/gw.env; set +a
(cd clients/js && npm install && npm test)
(cd clients/python && python -m unittest discover -s tests)
(cd clients/rust && cargo test)
scripts/start-test-gateway.sh --stop
```
